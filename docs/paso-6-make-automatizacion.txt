PASO 6 — Make.com: Automatización de Leads con IA
================================================================
Versión: v2.0.0
Fecha:   2026-08-29
Autor:   Bryan GP / BryTech Solutions

----------------------------------------------------------------
OBJETIVO
----------------------------------------------------------------
Automatizar el flujo completo de un lead desde que llena el
formulario de contacto en la web hasta que:
  1. La IA (OpenAI) analiza y estima el proyecto.
  2. El lead se guarda en Google Sheets.
  3. Bryan recibe un email con el análisis detallado.

----------------------------------------------------------------
ARQUITECTURA DEL FLUJO
----------------------------------------------------------------

  [Formulario Web]
       │
       ▼ POST /api/lead  (Vercel Serverless — seguro)
  [api/lead.js]
       │  Lee MAKE_WEBHOOK_URL de process.env
       │  (URL nunca expuesta en el bundle JS del frontend)
       ▼
  [Make.com Webhook]
       │
       ├──▶ Módulo HTTP  → POST /api/chat
       │         │         (OpenAI gpt-4o-mini + Pricing Engine)
       │         ▼
       │    Respuesta JSON:
       │      { interpretation: { projectType, complexity, summary },
       │        estimate: { estimatedMin, estimatedMax, ... } }
       │
       ├──▶ Módulo Google Sheets → Add a Row
       │         Columnas: Fecha | Nombre | Email | Teléfono |
       │                   Tipo Proyecto | Complejidad |
       │                   Estimado Min | Estimado Max
       │
       └──▶ Módulo Gmail → Send an Email
                 Subject: 🔔 Nuevo lead BryTech — {tipo} — ${min}–${max} MXN
                 Body:    HTML con datos del cliente + análisis de IA

----------------------------------------------------------------

----------------------------------------------------------------
BUG RESUELTO — vercel.json SPA rewrite (2026-08-31)
----------------------------------------------------------------
SÍNTOMA:
  Al correr `vercel dev`, el frontend cargaba sin CSS ni JS.
  El sitio se veía como HTML plano sin estilos.

CAUSA:
  La rewrite SPA en vercel.json era demasiado amplia:
    "/((?!api/).*)" → "/index.html"
  Interceptaba TODAS las peticiones que no comenzaran con /api/,
  incluyendo las peticiones de módulos del servidor de desarrollo
  de Vite: /@vite/client, /src/main.js, /src/style.css, etc.
  Vite recibía index.html en lugar del módulo JS, y su plugin
  vite:import-analysis fallaba al parsear HTML como JavaScript
  (el símbolo @ del email bryanalejandroprog17@gmail.com en el
  comentario del archivo activaba el error de sintaxis).

SOLUCIÓN:
  Se ajustó el patrón para excluir:
    - Rutas que empiecen con @  (módulos internos de Vite)
    - Rutas que empiecen con src/
    - Rutas que empiecen con node_modules/
    - Rutas con extensión de archivo (.js, .css, .svg, etc.)

  Nuevo patrón:
    "/((?!api/|@|src/|node_modules/)(?!.*\\.[a-z0-9]+$).*)"

  Esto garantiza que el SPA fallback solo aplica a rutas de
  navegación puras (sin extensión) como /contacto, /about, etc.
  tanto en desarrollo (vercel dev) como en producción.

COMMIT: fix: narrow SPA rewrite in vercel.json to not intercept
        Vite dev module requests
